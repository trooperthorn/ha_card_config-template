# config-template-card fork: upstream triage and adoption plan (2026-09-08)

Fork: github.com/trooperthorn/ha_card_config-template, cloned to ~/repos/ha_card_config-template with `upstream` = iantrich/config-template-card. The fork is at upstream `master` (17a4d22, 1.3.1 in package.json, last released as 1.3.6 in 2021). Scanner: zero findings. Comment inventory: one comment line in 258.

## 1. The lit-element warning is real and comes from master

`src/config-template-card.ts` line 1 on master imports `LitElement, html, customElement, property, ...` from `lit-element`, and package.json pins `lit ^2.0.0-rc.2`. That is exactly the deprecated entrypoint the console warning names. Every 1.3.x release, which is what HACS installs as "latest", carries it. The `beta` branch (2.0.0-b2) already imports from `lit` and `lit/decorators.js` on Lit 3.3, so moving the fork onto beta closes the warning. Note: the card is by Ian Richardson (iantrich), not Thomas Lovén; the pasted report misattributes it.

Not actionable in the fork: issues 112 and 144 (child card destroyed and recreated on every update, no `hass` pushed in place) are the card's architecture. ## 5. Baseline gap on the fork (reported, not applied)

- Default branch is `master`; the fork carries all 17 upstream branches. Baseline wants `main` only, with the upstream branch set left untouched on the remote.
- No releases on the fork, no `.release.json`, no branch protection, `delete_branch_on_merge` false.
- Workflows on master use unpinned `actions/checkout@v1`; the two Claude workflows need a `CLAUDE_CODE_OAUTH_TOKEN` secret the fork does not have. Delete both. beta's build.yml (Node 24, yarn 4 via corepack, `yarn build` = lint + vitest + rollup) is the right gate. beta's release.yml bumps versions from the tag at release time, the reverse of the manifest-driven invariant; replace it with the ha_card_music shape (`.release.json` with `version_fields` for package.json and src/const.ts, Prepare release, Release on merge to main).
- hacs.json on master has `homeassistant: 0.110.0` and no `filename`; beta drops the floor and adds `filename`. Set `homeassistant` to the floor the fork actually tests against and ship dist/config-template-card.js per HACS search order (dist, then release asset, then root).
- No node on this workstation; the gate runs in WSL or CI only.

## 6. Whether the fork is worth it for your dashboards

Your only use (`dashboards/tablet.yaml` line 174) wraps a modern-circular-gauge with no `${}` in it, and the 2026-09-08 alternatives audit already recommends unwrapping and uninstalling. A maintained fork only earns its keep if you intend to template child config later; Button Card `custom_fields` already covers that with in-place `hass` updates. Recommendation: do items 1 to 5 as one PR on a `main` cut from `upstream/beta` if you want a published fix for the community and for the lit-element warning, and still unwrap the gauge.
